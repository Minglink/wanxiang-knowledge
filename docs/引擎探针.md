## 0.5 embedding

`scripts/probes/embedding.mjs` 在同一已安装 Electron 运行时中构造真实 Cordis Context 与宿主 LlmRuntime，并检查 `ctx.llm` 的数据描述符和原型函数名，不访问 getter、凭据、供应商配置，也不发送测试文本。默认关闭；显式 `--run` 才执行。结果 `dist/v02-probes/embedding.json`：

```json
{"servicePresent":true,"prepareCall":true,"embeddingMethods":[],"supported":false,"enabled":false}
```

同时静态搜索解包的 `dsh-llm`、`dsh-llm-deepseek`、`dsh-llm-pi-ai`、account 和 api-key 包内 JS/TS 的独立 embed/embedding/embeddings 词，没有匹配。结论是 **已检查的此版本公共 ctx.llm 没有可调用的 embedding 能力**，不代表模型供应商的远程服务不存在 embedding，也不代表将来宿主没有。探针未加载生产配置；未对生产 ctx 的第三方动态扩展作穷尽断言。

后续向量保持 Off，按产品决定自动使用关键词/FTS 路径、无错误提示，不注册虚构端点，不主动请求外部 embedding。若未来能力出现，必须再次确认接口签名与宿主确实启用后再发送已经 redacted 的文本；仅方法名匹配不足以作为生产启用判据。
