## 路径结论

**选定 A：`systemPrompt.section()` 是可用的官方动态 system 扩展点。** 通过实际宿主导出的 SystemPrompt 在隔离进程验证动态文本、撤销注册、按字面保留 `{{...}}`。后续使用 section 时必须 `interpolate:false`，以免知识文本被解释成宿主模板变量。召回查询需在 section 求值之前完成/有预算兜底；不能在 pre-step 里更新结果却期待已完成的同一步 assemble 重新执行。

B：不要直接在 `session/event:user/message` 里追加所谓“隐藏 developer 消息”；未找到这样的官方隐藏上下文承诺。已验证的 pre-step 扩展 messages 是 **user** 角色，日志可见，可作为资料路径备选，但与目标 system/developer 级语义不同。

C：工具注册已由现有插件验证；systemPrompt.section 也可承载常驻规则。当前不需要宣判“宿主无法注入”，后续默认档位维持产品确定的**自动注入**。宿主能力消失时再按产品规则降级“仅提示”。

## 压缩、KV、事件日志三个问题

1. **压缩会不会丢失？** 会影响旧的 model-visible surface：尾部 system/message 可以被压缩替换，原事件仍在持久日志；系统头 node 0 受保护。`dsh-compaction-basic` 的 systemHead 与 cutoff 逻辑保留头部。隔离 Session 实测：尾部 marker 经与压缩相同的 positional replace 后离开 surface，但 snapshotEvents 仍含原 system/message。动态 section 注册独立于历史，下一次 assemble 仍产出当前文本，因此后续实现必须按当前查询重新供给，不能只注入一次就假定永存。**真实模型生成摘要的 compact 尚未测**。
2. **会不会影响 KV cache？** 条件性影响。源码表明：provider 声明 `systemPromptUpdate:'in-history'` 且 request series 未改变时，系统变更追加在历史后方，保留此前前缀；无该能力、series 重开或空文本时会替换系统头，失去该位置之后的前缀复用。`dsh-llm-deepseek/lib/index.js` 支持 in-history，但这是每条路由/模型的能力，不能推广到所有模型。**实际 cached_tokens、命中率、计费变化未测**；不得承诺“零影响”。
3. **事件日志可见吗？** 可见。loop 以 `session.append('system/message', {turn,step,message}, intent)` 记录；pre-step 扩展则是 user/message。Session contract 实测 marker 存在于 snapshotEvents；生产宿主 JSONL 的端到端落盘未测。UI 是否展示该内部消息与日志存在是两回事。

## 最小探针

- `scripts/probes/injection-observer.mjs`：独立插件，`enabled` 默认 false；开启只记录事件类型、段数和消息数，不记录正文、会话ID、凭据或修改 decision；未接入生产插件。
- `scripts/probes/injection-contract.mjs`：默认不运行，`--run` 后从**已安装 app.asar**加载真实 Cordis/SystemPrompt/Session；不执行解包树代码、不调用模型、不改生产会话。结果 `dist/v02-probes/injection.json`。
- 执行方式：用 node child_process.spawnSync 启动安装目录 `DeepSeek Harness.exe --expose-internals scripts/probes/injection-contract.mjs --run`，环境 `ELECTRON_RUN_AS_NODE=1`、`windowsHide:true`；直接用普通 Node 不能读取 app.asar 内模块。
- 自动化通过：默认零注册、动态 system 段、字面大括号、撤销、surface 替换、日志保留、下一次 assemble 重建。
- 未测：在线 provider 请求、真实 compact 摘要、KV 统计、生产热加载。这些不被标作已通过；第3期实现前必须补上请求链路/超时/宿主能力消失回归。

本期无模型输入路径，不发送知识文本；没有更改默认档位或对外行为。
