# CWE-763: 释放无效指针或引用

## 缺陷定义

产品试图将内存资源返回给系统，但调用了错误的释放函数，或者不正确地调用了适当的释放函数。

## 机制与扩展说明

此弱点有多种表现形式，例如：
内存通过某种内存管理方法（显式或隐式）分配，却使用另一种不兼容的函数进行释放（
CWE-762
）。
所选择的函数调用或内存管理例程是适当的，但使用方式不正确，例如
CWE-761
中的情况。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
修改内存；DoS：崩溃、退出或重启；执行未经授权的代码或命令
范围：完整性、可用性、机密性
此弱点可能导致内存损坏，甚至指令损坏，从而导致程序崩溃。如果损坏的内存可以被有效控制，则有可能执行任意代码。

## 预防与缓解措施

阶段
缓解措施
实施
仅调用相匹配的内存管理函数。不要混用例程。例如，当你使用 malloc() 分配缓冲区时，请使用 free() 释放原始指针。
实施
在 C++ 中编程时，请考虑使用 Boost 库提供的智能指针，以帮助正确且一致地管理内存。
架构与设计
策略：
库或框架
使用经过审查的库或框架，该库或框架不允许此弱点发生，或提供使此弱点更容易避免的结构。
例如，Linux 中的 glibc 提供了防止释放无效指针的保护机制。
架构与设计
使用提供内存分配和释放抽象的语言。

## 官方英文定义（核对锚点）

Release of Invalid Pointer or Reference

The product attempts to return a memory resource to the system, but it calls the wrong release function or calls the appropriate release function incorrectly.
