# CWE-73: 文件名或路径的外部控制

## 缺陷定义

产品允许用户输入控制或影响文件系统操作中使用的路径或文件名。

## 机制与扩展说明

这可能允许攻击者访问或修改系统文件或其他对应用程序至关重要的文件。
当满足以下两个条件时，就会出现路径操纵错误：
1. 攻击者可以指定在文件系统操作中使用的路径。
2. 通过指定资源，攻击者获得了原本不被允许的操作能力。
例如，程序可能会赋予攻击者覆盖指定文件或以攻击者控制的配置运行的能力。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
读取文件或目录；修改文件或目录
范围: 完整性，机密性
应用程序可能会对意外的文件进行操作。当目标文件名不是攻击者可以直接读取的文件时，机密性会受到侵犯。
修改文件或目录；执行未经授权的代码或命令
范围：完整性、机密性、可用性
应用程序可能会对意外的文件进行操作。如果对文件名进行了写入操作，或者该文件名是程序或其他形式的可执行代码，这可能会破坏完整性。
拒绝服务 (DoS)：崩溃、退出或重启；拒绝服务 (DoS)：资源消耗（其他）
范围：可用性
应用程序可能会对意外的文件进行操作。如果攻击者指定了应用程序修改的意外文件，可用性可能会受到破坏。如果攻击者为大文件指定了文件名，或者指向特殊设备或格式不符合应用程序预期的文件，可用性也可能受到影响。

## 预防与缓解措施

阶段
缓解措施
架构与设计
当文件名集合有限或已知时，创建从一组固定输入值（如数字 ID）到实际文件名的映射，并拒绝所有其他输入。例如，ID 1 可以映射到 "inbox.txt"，ID 2 可以映射到 "profile.txt"。诸如 ESAPI AccessReferenceMap 之类的功能提供了这种能力。
架构与设计；运维
在“监狱”或类似的沙盒环境中运行代码，该环境在进程和操作系统之间强制执行严格的边界。这可以有效地限制对特定目录内文件的所有访问。
示例包括 Unix chroot 监狱和 AppArmor。通常，托管代码可能提供一定的保护。
这可能不是一个可行的解决方案，并且它仅将影响限制在操作系统；您的应用程序其余部分可能仍然容易受到损害。
小心避免
CWE-243
以及与囚笼相关的其他弱点。
架构与设计
对于在客户端执行的任何安全检查，请确保在服务器端重复这些检查，以避免
CWE-602
。攻击者可以通过在检查执行后修改值，或修改客户端以完全移除客户端检查来绕过这些检查。随后，这些被修改的值将被提交到服务器。
实施
策略：
输入验证
假设所有输入都是恶意的。采用“接受已知良好”的输入验证策略，即使用严格符合规范的可接受输入列表。拒绝任何不严格符合规范的输入，或将其转换为符合规范的内容。
在执行输入验证时，考虑所有潜在相关的属性，包括长度、输入类型、可接受值的全部范围、缺失或额外的输入、语法、跨相关字段的一致性以及对业务规则的符合性。作为业务规则逻辑的一个例子，“boat”在语法上可能是有效的，因为它只包含字母数字字符，但如果输入只预期包含“red”或“blue”等颜色，则它无效。
不要仅仅依赖查找恶意或畸形输入。这很可能会遗漏至少一种不受欢迎的输入，尤其是当代码环境发生变化时。这可能给攻击者留出绕过预期验证的空间。不过，黑名单对于检测潜在攻击或确定哪些输入由于严重畸形而应被直接拒绝是有用的。
在验证文件名时，请使用严格的允许列表，限制所使用的字符集。如果可行，文件名中仅允许使用单个 "." 字符，以避免诸如
CWE-23
之类的弱点；并排除目录分隔符（如 "/"），以避免
CWE-36
。使用允许的文件扩展名列表将有助于避免
CWE-434
。
不要仅依赖于移除潜在危险字符的过滤机制。这等同于黑名单，可能是不完整的 (
CWE-184
)。例如，如果文件系统也支持使用 "\" 作为目录分隔符，则仅过滤 "/" 是不够的。当过滤方式导致仍产生危险数据时，也可能出现错误 (
CWE-182
)。例如，如果从字符串 ".../...//" 中按顺序移除了 "../" 序列，则会从原始字符串中移除两个 "../" 实例，但剩余的字符仍会形成 "../" 字符串。
有效性：高
实施
使用内置的路径规范化函数（如 C 语言中的 realpath()），该函数会生成路径名的规范版本，从而有效移除 ".." 序列和符号链接 (
CWE-23
,
CWE-59
)。
安装；操作
使用操作系统级别的权限并以低权限用户身份运行，以限制任何成功攻击的影响范围。
操作；实现
如果您正在使用 PHP，请配置您的应用程序，使其不使用 register_globals。在实现过程中，开发您的应用程序时应使其不依赖此功能，但要警惕实现容易受到
CWE-95
、
CWE-621
等类似问题影响的 register_globals 模拟。
测试
使用需要手动（人工）分析的工具和技术，例如渗透测试、威胁建模和交互式工具，允许测试人员记录和修改活动会话。这些可能比严格的自动化技术更有效。对于与设计和业务规则相关的弱点尤其如此。

## 补充说明与边界

关系
对文件名的外部控制可以成为与其他文件相关弱点链中的主要环节，如 CanPrecede 关系所示。这是因为软件系统将文件用于多种用途：执行程序、加载代码库、存储应用程序数据、存储配置设置、记录临时数据、作为其他进程的信号或信号量等。
然而，这些弱点并不总是需要外部控制。例如，链接跟随弱点 (
CWE-59
) 通常涉及攻击者根本无法控制的路径名。
外部控制可能是其他问题的结果。例如，在 PHP 应用程序中，register_globals 设置可能允许攻击者修改程序员认为不可变的变量，从而启用文件包含 (
CWE-98
) 和路径遍历 (
CWE-22
)。以过高的权限运行 (
CWE-250
) 可能允许攻击者指定一个攻击者无法直接读取但特权程序可访问的输入文件名。缓冲区溢出 (
CWE-119
) 可能使攻击者控制与路径名相关但攻击者无法直接修改的附近内存位置。
维护
CWE-114
是一个类，但在视图 1000 中被列为
CWE-73

The product allows user input to control or influence paths or file names that are used in filesystem operations.
