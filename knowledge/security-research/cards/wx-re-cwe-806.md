# CWE-806：使用源缓冲区大小访问缓冲区

## 缺陷定义

产品在从目标缓冲区读取或写入目标缓冲区时使用源缓冲区的大小，这可能导致其访问缓冲区边界之外的内存。

## 机制与扩展说明

当目标缓冲区的大小小于源缓冲区的大小时，可能会发生缓冲区溢出。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
修改内存；DoS：崩溃、退出或重启；DoS：资源消耗 (CPU)
范围：可用性
缓冲区溢出通常会导致程序崩溃。其他导致可用性丧失的攻击也是可能的，包括使程序进入无限循环。
读取内存；修改内存；执行未经授权的代码或命令
范围：完整性、机密性、可用性
缓冲区溢出通常可用于执行任意代码，这通常超出程序隐式安全策略的范围。
绕过保护机制
范围: 访问控制
当后果是任意代码执行时，这通常可以用来破坏任何其他安全服务。

## 预防与缓解措施

阶段
缓解措施
架构与设计
使用抽象库来抽象化有风险的 API。示例包括 Viega 的 Safe C 字符串库 (SafeStr) 和微软的 Strsafe.h 库。这不是一个完整的解决方案，因为许多缓冲区溢出与字符串无关。
操作；构建与编译
策略：
环境强化
使用某些编译器或编译器扩展提供的自动缓冲区溢出检测机制。示例包括：Microsoft Visual Studio 的 /GS 标志、Fedora/Red Hat 的 FORTIFY_SOURCE GCC 标志、StackGuard 和 ProPolice，它们提供各种机制，包括基于金丝雀（canary）的检测和范围/索引检查。
来自 D3FEND 的 D3-SFCV（堆栈帧 Canary 验证）[
REF-1334
] 详细讨论了基于 Canary 的检测。
有效性：纵深防御
注意：
这不一定是一个完整的解决方案，因为这些机制只能检测某些类型的溢出。此外，结果仍然是拒绝服务，因为典型的响应是退出应用程序。
实施
程序员在分配和管理应用程序内存时应遵循以下规则：仔细检查您的缓冲区是否与您指定的大小相同。当使用接受要复制的字节数的函数（例如 strncpy()）时，请注意，如果目标缓冲区大小等于源缓冲区大小，它可能不会以 NULL 终止字符串。如果在循环中调用此函数，请检查缓冲区边界，确保没有写入超出分配空间的危险。在将所有输入字符串传递给复制和连接函数之前，将其截断到合理的长度。
操作；构建与编译
策略：
环境强化
使用在内存中随机排列程序可执行文件和库位置的功能或扩展来运行或编译软件。由于这使得地址不可预测，它可以防止攻击者可靠地跳转到可利用的代码。
示例包括地址空间布局随机化 (ASLR) [
REF-58
] [
REF-60
] 和位置无关可执行文件 (PIE) [
REF-64
]。如果导入模块的默认内存地址与其他模块冲突，它们可能会被类似地重新对齐，这个过程在 Windows 上称为“重基”(rebasing)，在 Linux 上称为“预链接”(prelinking) [
REF-1332
]，使用随机生成的地址。库的 ASLR 不能与预链接结合使用，因为它需要运行时重新定位库，从而破坏了预链接的全部目的。
有关这些技术的更多信息，请参阅 D3FEND 中的 D3-SAOR（段地址偏移随机化）[
REF-1335
]。
有效性：纵深防御
注意：
这些技术不能提供完整的解决方案。例如，攻击通常会利用披露内存地址的漏洞，以最大化代码执行的可靠性 [
REF-1337
]。也有研究表明，侧信道攻击可以绕过 ASLR [
REF-1333
]。
运营
策略：
环境强化
使用提供数据执行保护（通过硬件 NX 或 XD 位）或在软件中模拟此功能的等效技术（例如 PaX [
REF-60
] [
REF-61
]）的 CPU 和操作系统。这些技术确保任何执行的指令都只位于代码段中的内存地址。
有关这些技术的更多信息，请参阅 D3FEND 中的 D3-PSEP（进程段执行预防）[
REF-1336
]。
有效性：纵深防御
注：
这不是一个完整的解决方案，因为缓冲区溢出可能被用来覆盖附近的变量，以危险的方式修改软件状态。此外，它不能用于需要自修改代码的情况。最后，攻击仍然可能导致拒绝服务，因为典型的响应是退出应用程序。
构建和编译；操作
迄今为止，编译器或操作系统级别的大多数缓解技术仅解决了缓冲区溢出问题的一个子集，即使针对该子集也很少提供完全保护。实施策略以增加攻击者的工作负载是一种好的做法，例如让攻击者猜测一个在每次程序执行时都会改变的未知值。

## 官方英文定义（核对锚点）

Buffer Access Using Size of Source Buffer

The product uses the size of a source buffer when reading from or writing to a destination buffer, which may cause it to access memory that is outside of the bounds of the buffer.
