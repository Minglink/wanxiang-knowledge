# CWE-918: 服务器端请求伪造 (SSRF)

## 缺陷定义

Web 服务器从上游组件接收 URL 或类似请求并检索该 URL 的内容，但它没有充分确保请求被发送到预期的目的地。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。

范围: 访问控制
通过提供指向意外主机或端口的 URL，攻击者可以让服务器看起来像是请求的发起者，从而可能绕过防火墙等访问控制，这些防火墙原本可以阻止攻击者直接访问相关 URL。服务器可被用作代理，对内部网络中的主机进行端口扫描，使用其他 URL（例如访问系统上的文档，使用 file:// 协议），或使用其他协议（如 gopher:// 或 tftp://），从而实现对请求内容的更强控制。

## 补充说明与边界

关系
CWE-918
(SSRF) 和
CWE-611
(XXE) 密切相关，因为它们都涉及与 Web 相关的技术，并且可以发起针对意外目标的出站请求。然而，XXE 可以在客户端执行，或者在软件不直接充当服务器的其他上下文中执行，因此 SSRF 首字母缩略词中的“服务器”部分并不一定适用。

## 官方英文定义（核对锚点）

Server-Side Request Forgery (SSRF)

The web server receives a URL or similar request from an upstream component and retrieves the contents of this URL, but it does not sufficiently ensure that the request is being sent to the expected destination.
