# CWE-352: 跨站请求伪造 (CSRF)

## 缺陷定义

Web 应用程序未能或无法充分验证请求是否由发送该请求的用户有意提供，而该请求可能源自未经授权的攻击者。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
获取权限或冒充身份；绕过保护机制；读取应用程序数据；修改应用程序数据；拒绝服务 (DoS)：崩溃、退出或重启
范围：机密性、完整性、可用性、不可抵赖性、访问控制
后果取决于易受 CSRF 攻击的功能性质。攻击者可以通过 URL、图像加载、XMLHttpRequest 等诱导客户端向 Web 服务器发出非自愿请求，服务器随后会将这些请求视为来自客户端的真实请求——从而以受害者的身份执行任何操作，导致数据泄露、非预期的代码执行等。如果受害者是管理员或特权用户，后果可能包括获得对 Web 应用程序的完全控制权——删除或窃取数据、卸载产品，或利用该产品对所有用户发起其他攻击。由于攻击者获得了受害者的身份，CSRF 的影响范围仅受限于受害者的权限。

库或框架

架构与设计
为每个表单生成一个唯一的随机数（Nonce），将其放入表单中，并在收到表单时进行验证。确保该随机数不可预测 (
CWE-330

REF-332
]

架构与设计
识别特别危险的操作。当用户执行危险操作时，发送一个单独的确认请求，以确保用户确实打算执行该操作。
注意：
请注意，这可以通过 XSS (
CWE-79
) 绕过。
架构与设计
使用 Felten 和 Zeller 描述的“双重提交 Cookie”方法
当用户访问网站时，站点应生成一个伪随机值并将其设置为用户机器上的 Cookie。站点应要求每次表单提交时，既要包含该值作为表单值，也要包含该值作为 Cookie 值。当向站点发送 POST 请求时，仅当表单值与 Cookie 值相同时，请求才被视为有效。
由于同源策略的限制，攻击者无法读取或修改存储在 Cookie 中的值。为了代表用户成功提交表单，攻击者必须正确猜测出伪随机值。如果该伪随机值在密码学上足够强大，这将是非常困难的。
此技术需要 Javascript，因此对于禁用 Javascript 的浏览器可能无效。 [
REF-331
]
注意：
请注意，这可能可以通过 XSS (
CWE-79
) 绕过，或者在使用允许攻击者读取 HTTP 请求原始头部的 Web 技术时也可以绕过。
架构与设计
不要对触发状态更改的任何请求使用 GET 方法。
实施
检查 HTTP Referer 头，查看请求是否源自预期的页面。这可能会破坏合法功能，因为用户或代理可能出于隐私原因禁用了发送 Referer。
注意：
请注意，这可以通过 XSS (
CWE-79
) 绕过。攻击者可以使用 XSS 生成伪造的 Referer，或从允许 Referer 的页面生成恶意请求。

## 补充说明与边界

关系
XSS 和 CSRF (
CWE-352
) 之间可能存在密切关系。攻击者可能使用 CSRF 诱导受害者向包含 XSS 载荷的服务器提交请求。一个著名的例子是 MySpace 上的 Samy 蠕虫 [
REF-956
]。该蠕虫利用 XSS 将恶意 HTML 序列插入用户的个人资料，并将攻击者添加为 MySpace 好友。该受害者的 MySpace 好友随后会执行该载荷以修改他们自己的个人资料，导致蠕虫呈指数级传播。由于受害者并非有意自行插入恶意脚本，CSRF 是根本原因。
理论性
CSRF 拓扑是多通道的
攻击者（作为局外人）到中间人（作为用户）。交互点是外部或内部通道。
中间人（作为用户）到服务器（作为受害者）。激活点是内部通道。

## 官方英文定义（核对锚点）

Cross-Site Request Forgery (CSRF)

The web application does not, or cannot, sufficiently verify whether a request was intentionally provided by the user who sent the request, which could have originated from an unauthorized actor.
