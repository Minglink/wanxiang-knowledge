# CWE-843: 使用不兼容类型访问资源（“类型混淆”）

## 缺陷定义

产品使用一种类型分配或初始化资源（例如指针、对象或变量），但随后使用与原始类型不兼容的类型来访问该资源。

## 机制与扩展说明

当产品使用不兼容的类型访问资源时，可能会触发逻辑错误，因为资源不具备预期的属性。在缺乏内存安全的语言（如 C 和 C++）中，类型混淆可能导致越界内存访问。
虽然此弱点经常与 C 语言中解析包含多种不同嵌入对象类型的数据时的联合体（union）相关联，但它可能存在于任何以多种方式解释相同变量或内存位置的应用程序中。
此弱点并非 C 和 C++ 所独有。例如，PHP 应用程序中的错误可能是由于在需要标量时提供了数组参数（反之亦然）而触发的。Perl 等在访问变量时会自动执行类型转换的语言，如果将变量以另一种类型访问，也可能包含这些问题。

## 补充说明与边界

适用平台
这种弱点在任何类型不安全的编程语言中都是可能的。
研究差距
类型混淆弱点已受到应用研究人员和主要软件供应商对 C 和 C++ 代码的关注。一些公开报道的漏洞可能以类型混淆作为根本弱点，但这些可能被描述为“内存损坏”。
对于其他语言，关于类型混淆弱点的公开报道很少。这些可能研究不足。由于许多程序直接或间接依赖于松散类型，潜在的“类型混淆”行为可能是故意的，可能需要更多的人工分析。

## 官方英文定义（核对锚点）

Access of Resource Using Incompatible Type ('Type Confusion')

The product allocates or initializes a resource such as a pointer, object, or variable using one type, but it later accesses that resource using a type that is incompatible with the original type.
