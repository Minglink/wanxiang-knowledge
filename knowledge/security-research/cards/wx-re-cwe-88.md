# CWE-88：命令中参数注入（“参数注入”）

## 缺陷定义

产品构造了一个字符串命令，由另一个控制域中的独立组件执行，但它没有正确地定界该命令字符串中预期的参数、选项或开关。

## 机制与扩展说明

当通过字符串插值创建命令时，开发人员可能假设只有他们指定的参数/选项会被处理。当程序员以防止恶意提供单独命令（例如使用 shell 元字符）的方式对命令进行编码时，这种假设可能更为强烈。在构建命令时，开发人员可能会使用分隔参数所需的空格或其他分隔符。然而，如果攻击者能够提供包含参数分隔符的不可信输入，那么生成的命令将拥有比开发人员预期的更多的参数。攻击者随后可能能够改变命令的行为。根据额外参数所支持的功能，这可能会产生安全相关的后果。

参数化

在执行输入验证时，考虑所有潜在相关的属性，包括长度、输入类型、可接受值的全部范围、缺失或额外的输入、语法、跨相关字段的一致性以及对业务规则的符合性。作为业务规则逻辑的一个例子，“boat”在语法上可能是有效的，因为它只包含字母数字字符，但如果输入只预期包含“red”或“blue”等颜色，则它无效。

## 官方英文定义（核对锚点）

Improper Neutralization of Argument Delimiters in a Command ('Argument Injection')

The product constructs a string for a command to be executed by a separate component
in another control sphere, but it does not properly delimit the
intended arguments, options, or switches within that command string.
