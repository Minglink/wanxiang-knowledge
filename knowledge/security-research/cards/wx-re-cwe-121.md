# CWE-121: 基于栈的缓冲区溢出

## 缺陷定义

基于栈的缓冲区溢出是一种状况，即被覆盖的缓冲区被分配在栈上（即局部变量，或者较少见的情况下，是函数的参数）。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
修改内存；拒绝服务 (DoS)：崩溃、退出或重启；拒绝服务 (DoS)：资源消耗 (CPU)；拒绝服务 (DoS)：资源消耗 (内存)
范围：可用性
缓冲区溢出通常会导致程序崩溃。其他导致可用性丧失的攻击也是可能的，包括使程序进入无限循环。
修改内存；执行未经授权的代码或命令；绕过保护机制
范围：完整性、机密性、可用性、访问控制
缓冲区溢出通常可用于执行任意代码，这通常超出了程序隐式安全策略的范围。

## 背景机制

执行栈上通常存在多个对安全至关重要的数据，它们可能导致任意代码执行。最显著的是存储的返回地址，即当前函数执行结束后执行流应继续的内存地址。攻击者可以用他们也拥有写权限的某个内存地址覆盖此值，并在该地址中放置任意代码，以利用受损程序的全部权限运行。或者，攻击者可以提供重要调用的地址，例如 POSIX system() 调用，并将调用的参数留在栈上。这通常被称为“返回到 libc”漏洞利用（return into libc exploit），因为攻击者通常强迫程序在返回时跳转到 C 标准库 (libc) 中的有趣例程。栈上其他常见的重要数据包括栈指针和帧指针，这两个值指示用于计算内存地址的偏移量。修改这些值通常可以利用为“写任意内容到任意位置”(write-what-where) 的状况。

## 补充说明与边界

关系
基于栈的缓冲区溢出可以体现为返回地址覆盖、栈指针覆盖或帧指针覆盖。它们也可以被视为函数指针覆盖、数组索引覆盖或“写任意内容到任意位置”等状况。
术语
关于“缓冲区溢出”一词存在严重的不一致，它可能有多种解释和用法。许多人将其理解为“写入超出缓冲区末尾”。其他人则将其理解为“写入超出缓冲区末尾，或在缓冲区开头之前”。还有一些人可能会将“读取”也包含在该术语中。

## 官方英文定义（核对锚点）

Stack-based Buffer Overflow

A stack-based buffer overflow condition is a condition where the buffer being overwritten is allocated on the stack (i.e., is a local variable or, rarely, a parameter to a function).
