# CWE-787: 越界写入

## 缺陷定义

产品在预期缓冲区末尾之后或开头之前写入数据。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
修改内存；执行未经授权的代码或命令
范围：完整性
写入操作可能导致内存损坏。在某些情况下，攻击者可以修改控制数据（如返回地址）以执行意外代码。
DoS：崩溃、退出或重启
范围：可用性
尝试访问范围外、无效或未经授权的内存可能会导致产品崩溃。
非预期状态
范围：其他
后续的写入操作可能会产生未定义或意外的结果。

## 预防与缓解措施

阶段
缓解措施
需求
策略：
语言选择
使用一种不允许此弱点发生或提供使此弱点更容易避免的结构的语言。
例如，许多自行管理内存的语言，如 Java 和 Perl，不易受到缓冲区溢出的影响。其他语言，如 Ada 和 C#，通常提供溢出保护，但程序员可以禁用该保护。
请注意，即使语言本身在理论上是安全的，语言到原生代码的接口可能仍然容易受到溢出的影响。
架构与设计
策略：
库或框架
使用经过审查的库或框架，该库或框架不允许此弱点发生，或提供使此弱点更容易避免的结构。
示例包括 Messier 和 Viega 的安全 C 字符串库 (SafeStr) [
REF-57
]，以及微软的 Strsafe.h 库 [
REF-56
]。这些库提供了易受溢出影响的字符串处理函数的更安全版本。
注意：
这不是一个完整的解决方案，因为许多缓冲区溢出与字符串无关。
操作；构建与编译
策略：
环境强化
使用某些编译器或编译器扩展提供的自动缓冲区溢出检测机制。示例包括：Microsoft Visual Studio 的 /GS 标志、Fedora/Red Hat 的 FORTIFY_SOURCE GCC 标志、StackGuard 和 ProPolice，它们提供各种机制，包括基于金丝雀（canary）的检测和范围/索引检查。
D3FEND 的 D3-SFCV（栈帧金丝雀验证）[
REF-1334
] 详细讨论了基于金丝雀（Canary）的检测方法。
有效性：纵深防御
注意：
这不一定是一个完整的解决方案，因为这些机制只能检测某些类型的溢出。此外，结果仍然是拒绝服务，因为典型的响应是退出应用程序。
实施
在分配和管理应用程序内存时，请考虑遵循以下规则
仔细检查缓冲区是否确实如指定的那么大。
使用接受要复制的字节数的函数（如 strncpy()）时，请注意，如果目标缓冲区大小等于源缓冲区大小，它可能不会 NULL 终止字符串。
如果在循环中访问缓冲区，请检查缓冲区边界，并确保不会写入超出分配空间的内容。
必要时，在将所有输入字符串传递给复制和连接函数之前，将其截断为合理的长度。
操作；构建与编译
策略：
环境强化
使用在内存中随机排列程序可执行文件和库位置的功能或扩展来运行或编译软件。由于这使得地址不可预测，它可以防止攻击者可靠地跳转到可利用的代码。
示例包括地址空间布局随机化 (ASLR) [
REF-58
] [
REF-60
] 和地址无关可执行文件 (PIE) [
REF-64
]。如果导入模块的默认内存地址与其他模块冲突，可以使用随机生成的地址以“重定向（rebasing，针对 Windows）”和“预链接（prelinking，针对 Linux）”的过程对导入模块进行类似重置 [
REF-1332
]。库的 ASLR 不能与预链接结合使用，因为这需要在运行时重新定位库，从而违背了预链接的初衷。
有关这些技术的更多信息，请参阅 D3FEND 的 D3-SAOR（段地址偏移随机化）[
REF-1335
]。
有效性：纵深防御
注意：
这些技术并不能提供完整的解决方案。例如，攻击经常利用披露内存地址的漏洞来最大化代码执行的可靠性 [
REF-1337
]。此外，已有研究表明侧信道攻击可以绕过 ASLR [
REF-1333
]。
运营
策略：
环境强化
使用提供数据执行保护（使用硬件 NX 或 XD 位）的 CPU 和操作系统，或在软件中模拟此功能的等效技术，例如 PaX [
REF-60
] [
REF-61
]。这些技术可确保执行的任何指令仅位于代码段的一部分内存地址中。
有关这些技术的更多信息，请参阅 D3FEND 的 D3-PSEP（进程段执行预防）[
REF-1336
]。
有效性：纵深防御
注：
这不是一个完整的解决方案，因为缓冲区溢出可能被用来覆盖附近的变量，以危险的方式修改软件状态。此外，它不能用于需要自修改代码的情况。最后，攻击仍然可能导致拒绝服务，因为典型的响应是退出应用程序。
实施
用支持长度参数的类似函数替换无界复制函数，例如用 strncpy 替换 strcpy。如果它们不可用，请创建它们。
有效性：中等
注意：
此方法仍然容易受到计算错误的影响，包括差一错误 (
CWE-193
) 和缓冲区长度计算错误 (
CWE-131
) 等问题。

## 检测与审计方法

方法
详细信息
自动化静态分析
该弱点通常可以使用自动化静态分析工具检测到。许多现代工具使用数据流分析或基于约束的技术来最大限度地减少误报。
自动静态分析在报告越界内存操作时通常不考虑环境因素。这可能使用户难以确定哪些警告应该优先调查。例如，分析工具可能会报告在非预期以 setuid 或其他特殊权限运行的程序中，源自命令行参数的缓冲区溢出。
有效性：高
注意：
缓冲区相关错误的检测技术比大多数其他弱点类型更成熟。
自动化动态分析
可以使用与软件交互的动态工具和技术来检测此弱点，这些工具使用带有许多多样化输入的大型测试套件，例如模糊测试 (fuzzing)、健壮性测试和故障注入。软件运行可能会变慢，但不应变得不稳定、崩溃或产生错误的结果。
自动化动态分析
使用编译时集成的工具来插入与内存安全错误相关的运行时错误检查机制，例如用于 C/C++ 的 AddressSanitizer (ASan) [
REF-1518
]。
有效性：中等
注：
需要精心设计的输入才能到达包含错误的各种代码路径，例如由模糊测试工具生成的输入。此外，这些工具可能会降低性能，并且它们仅报告错误情况——而不是导致错误的原始失误。

## 官方英文定义（核对锚点）

Out-of-bounds Write

The product writes data past the end, or before the beginning, of the intended buffer.
