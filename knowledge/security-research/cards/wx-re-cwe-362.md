# CWE-362: 使用同步不当的共享资源进行并发执行（“竞争条件”）

## 缺陷定义

产品包含一个并发代码序列，该序列需要对共享资源进行临时的排他性访问，但存在一个时间窗口，在此窗口内，该共享资源可以被另一个并发运行的代码序列修改。

## 机制与扩展说明

竞争条件发生在并发环境中，它实质上是代码序列的一种属性。根据上下文的不同，代码序列可以是函数调用、少数几条指令、一系列程序调用等形式。
竞争条件违反了以下密切相关的属性：
排他性（Exclusivity） - 代码序列被赋予对共享资源的排他性访问权，即在原始序列完成执行之前，没有其他代码序列可以修改共享资源的属性。
原子性（Atomicity） - 代码序列在行为上是原子的，即没有其他线程或进程可以针对同一资源并发执行相同的指令序列（或子集）。
当“干扰代码序列”仍能访问共享资源时，就会存在竞争条件，从而违反了排他性。
干扰代码序列可以是“受信任的”或“非受信任的”。受信任的干扰代码序列发生在产品内部；它无法被攻击者修改，且只能被间接调用。非受信任的干扰代码序列可以由攻击者直接编写，通常存在于受攻击产品之外。

## 补充说明与边界

研究差距
Web 应用程序中的竞争条件尚未得到充分研究，且可能存在漏报的情况。然而，自 2008 年以来，人们对这一领域的关注度日益增加。
研究差距
竞争条件研究的大部分焦点都集中在检查时间到使用时间（TOCTOU）变体（
CWE-367
）上，但许多竞争条件与同步问题有关，这些问题并不一定需要检查时间。
研究差距
从分类学/分类体系的角度来看，并发与程序状态之间的关系需要更深入的调查，这对于整理相关问题可能会有用。
维护
竞争条件与同步问题（
CWE-662
）之间的关系需要进一步阐明。它们并不一定是同一核心概念的两个视角，因为同步只是避免竞争条件的一种技术，而且同步还可以用于除防止竞争条件之外的其他目的。

## 官方英文定义（核对锚点）

Concurrent Execution using Shared Resource with Improper Synchronization ('Race Condition')

The product contains a concurrent code sequence that requires temporary, exclusive access to a shared resource, but a timing window exists in which the shared resource can be modified by another code sequence operating concurrently.
