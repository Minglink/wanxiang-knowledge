# CWE-648：特权 API 使用不当

## 缺陷定义

产品不符合需要额外权限的函数调用 API 要求。这可能允许攻击者通过诱导函数被错误调用来获取权限。

## 机制与扩展说明

当产品包含某些需要提升权限级别才能执行操作的函数时，特权 API 的调用者必须小心
确保 API 所做出的假设是有效的，例如参数的有效性
考虑到 API 设计/实现中已知的弱点
在安全的上下文中调用 API
如果 API 的调用者不遵循这些要求，那么它可能允许恶意用户或进程提升其权限、劫持进程或窃取敏感数据。
例如，了解特权 API 在返回给调用者之前是否会放弃其特权，或者特权函数是否可能对调用者传递给它的数据、上下文或状态信息做出某些假设，这一点非常重要。始终了解何时以及如何调用特权 API 以确保其提升的特权级别无法被利用，这一点至关重要。

## 预防与缓解措施

阶段
缓解措施
实施
在调用特权 API 之前，始终确保在进行调用之前特权代码所做的假设成立。
架构与设计
了解特权 API 的架构和实现弱点，并确保在调用特权 API 之前考虑到这些弱点，以确保它们可以被安全地调用。
实施
如果特权 API 对调用者传递的数据、上下文或状态有效性做出某些假设，则调用代码必须确保在进行调用之前已验证这些假设。
实施
如果特权 API 在返回调用代码之前不放弃其特权，则调用代码需要在调用特权 API 之后立即安全地放弃这些特权。特别是，调用代码需要确保特权执行线程永远不会返回给用户或提供给用户控制的进程。
实施
仅在安全、一致和预期的状态下调用特权 API。
实施
确保故障或错误不会使系统处于特权无法正确放弃且可能导致权限提升的状态（即在处理特权方面安全失败）。

## 官方英文定义（核对锚点）

Incorrect Use of Privileged APIs

The product does not conform to the API requirements for a function call that requires extra privileges. This could allow attackers to gain privileges by causing the function to be called incorrectly.
