# CWE-14: 编译器移除清理缓冲区的代码

## 缺陷定义

敏感内存根据源代码进行了清除，但编译器优化使得当内存不再被读取时保持原样，即所谓的“死存储移除（dead store removal）”。

## 机制与扩展说明

这种编译器优化错误发生在：
机密数据存储在内存中。
通过覆盖机密数据的内容，将其从内存中清除。
源码使用优化编译器进行编译，编译器由于该内存后续不再使用，将覆盖内容的函数识别为“死存储（dead store）”并将其移除。

详细信息

范围：机密性，访问控制
该弱点将允许读取未从内存中清除的数据。如果这些数据包含敏感的密码信息，那么攻击者就可以读取密码并利用这些信息绕过保护机制。

## 预防与缓解措施

阶段
缓解措施
实施
如果可用，将敏感数据存储在“volatile”内存位置。
构建与编译
如果可能，配置编译器，使其不移除死存储。
架构与设计
在可能的情况下，加密软件系统使用的敏感数据。

## 检测与审计方法

方法
详细信息
黑盒测试
这种特定的弱点无法使用黑盒方法检测。虽然分析人员可以检查内存以查看其是否已被清理，但对可执行文件的分析不会成功。这是因为编译器已经移除了相关代码。只有源代码能显示程序员是否打算清除内存，因此这种弱点与其他弱点是无法区分的。
有效性：有限
白盒测试
这种弱点只能使用白盒方法检测（见黑盒检测因素）。需要仔细分析以确定代码是否可能被编译器移除。

## 官方英文定义（核对锚点）

Compiler Removal of Code to Clear Buffers

Sensitive memory is cleared according to the source code, but compiler optimizations leave the memory untouched when it is not read from again, aka "dead store removal."
