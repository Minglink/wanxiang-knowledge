# CWE-38: 路径遍历：'\absolute\pathname\here'

## 缺陷定义

产品在没有适当验证的情况下接受反斜杠绝对路径（'\absolute\pathname\here'）形式的输入，这可能允许攻击者遍历文件系统到意外位置或访问任意文件。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
读取文件或目录；修改文件或目录
范围：机密性、完整性

策略：
输入验证
假设所有输入都是恶意的。采用“接受已知良好”的输入验证策略，即使用严格符合规范的可接受输入列表。拒绝任何不严格符合规范的输入，或将其转换为符合规范的内容。
在执行输入验证时，考虑所有潜在相关的属性，包括长度、输入类型、可接受值的全部范围、缺失或额外的输入、语法、跨相关字段的一致性以及对业务规则的符合性。作为业务规则逻辑的一个例子，“boat”在语法上可能是有效的，因为它只包含字母数字字符，但如果输入只预期包含“red”或“blue”等颜色，则它无效。
不要仅仅依赖查找恶意或畸形输入。这很可能会遗漏至少一种不受欢迎的输入，尤其是当代码环境发生变化时。这可能给攻击者留出绕过预期验证的空间。不过，黑名单对于检测潜在攻击或确定哪些输入由于严重畸形而应被直接拒绝是有用的。
在验证文件名时，请使用严格的允许列表，限制所使用的字符集。如果可行，文件名中仅允许使用单个 "." 字符，以避免诸如
CWE-23
之类的弱点；并排除目录分隔符（如 "/"），以避免
CWE-36
。使用允许的文件扩展名列表将有助于避免
CWE-434
。
不要仅依赖于移除潜在危险字符的过滤机制。这等同于黑名单，可能是不完整的 (
CWE-184
)。例如，如果文件系统也支持使用 "\" 作为目录分隔符，则仅过滤 "/" 是不够的。当过滤方式导致仍产生危险数据时，也可能出现错误 (
CWE-182
)。例如，如果从字符串 ".../...//" 中按顺序移除了 "../" 序列，则会从原始字符串中移除两个 "../" 实例，但剩余的字符仍会形成 "../" 字符串。
有效性：高

## 官方英文定义（核对锚点）

Path Traversal: '\absolute\pathname\here'

The product accepts input in the form of a backslash absolute path ('\absolute\pathname\here') without appropriate validation, which can allow an attacker to traverse the file system to unintended locations or access arbitrary files.
