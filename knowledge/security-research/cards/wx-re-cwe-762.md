# CWE-762：不匹配的内存管理例程

## 缺陷定义

产品试图将内存资源返回给系统，但调用了与最初用于分配该资源的函数不兼容的释放函数。

## 机制与扩展说明

该弱点通常被描述为内存管理例程的不匹配，例如：
内存是在栈上分配的（自动分配），但却使用本应处理显式分配的堆内存的内存管理例程 free() 进行了释放（
CWE-590
）。
内存使用一组内存管理函数显式分配，却使用另一组函数进行释放。例如，在 C++ 中可能使用 malloc() 而非 new 运算符来分配内存，然后却使用 delete 运算符进行释放。
当内存管理函数不匹配时，后果可能非常严重，包括代码执行、内存损坏或程序崩溃。后果及利用难易程度取决于相关例程的实现以及被管理的对象的类型。

## 预防与缓解措施

阶段
缓解措施
实施
仅调用相互匹配的内存管理函数。不要混用例程。例如，当使用 malloc() 分配缓冲区时，请使用 free() 释放原始指针。
实施
策略：
库或框架
选择提供自动内存管理，或使手动内存管理不易出错的编程语言或工具。
例如，Linux 中的 glibc 提供了防止释放无效指针的保护机制。
在使用 Xcode 针对 OS X 或 iOS 进行开发时，启用自动引用计数 (ARC) [
REF-391
]。
为了在 C++ 编程中正确且一致地管理内存，请考虑使用智能指针类，例如 std::auto_ptr（由 ISO/IEC 14882:2003 定义）、std::shared_ptr 和 std::unique_ptr（由 C++ 标准的后续修订版指定，非正式称为 C++ 1x），或类似的解决方案（如 Boost）。

## 官方英文定义（核对锚点）

Mismatched Memory Management Routines

The product attempts to return a memory resource to the system, but it calls a release function that is not compatible with the function that was originally used to allocate that resource.
