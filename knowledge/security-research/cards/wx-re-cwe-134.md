# CWE-134: 使用外部可控格式字符串

## 缺陷定义

该产品使用了接受格式字符串作为参数的函数，但该格式字符串来源于外部源。

实施
程序员很少有意让格式字符串被外部控制。这种弱点通常引入于构建日志信息的代码中，且遗漏了常量格式字符串。

## 补充说明与边界

适用平台
此弱点可能存在于任何支持格式字符串的编程语言中。
研究差距
除 C 语言外，其他语言的格式字符串问题研究不足。在 Perl、PHP、Python 等语言编写的应用程序中，格式字符串利用可能导致内存或磁盘消耗、控制流或变量改变以及数据损坏。
其他
在某些情况下（如国际化），格式字符串集合在设计上是外部可控的。如果这些格式字符串的来源是受信任的（例如仅包含在只能由系统管理员修改的库文件中），那么外部控制本身可能不会构成漏洞。
虽然格式字符串漏洞通常属于缓冲区溢出类别，但从技术上讲它们并非溢出的缓冲区。格式字符串漏洞相当新（约 1999 年左右），其根源在于：对于采用可变数量参数的函数，没有任何现实的方法来确定到底传递了多少个参数。最常见的采用可变参数的函数（包括 C 运行时函数）是 printf() 调用族。格式字符串问题以多种方式出现。没有格式说明符的 *printf() 调用是危险的，并且可以被利用。例如，printf(input); 是可利用的，而 printf(y, input); 在该上下文中不可利用。第一个调用使用不当，允许攻击者窥探栈内存，因为输入字符串将被用作格式说明符。攻击者可以用格式说明符填充输入字符串并开始读取栈值，因为剩余的参数将从栈中拉取。最坏的情况下，这种不当使用可能泄露足够的控制权，允许将任意值（在攻击程序的情况下为多个值）写入正在运行的程序的内存中。
经常被攻击的对象是文件名、进程名、标识符。
格式字符串问题是一个经典的 C/C++ 问题，由于易于发现，现在已很少见。格式字符串漏洞之所以能够被利用，主要原因之一是 %n 操作符。%n 操作符会将到目前为止已打印出的字符数写入其参数所指向的内存中。通过技巧性地创建格式字符串，恶意用户可以使用栈上的值来创建“写什么到哪里”(write-what-where) 条件。一旦达到此目的，他们就可以执行任意代码。也可以使用其他操作符；例如，%9999s 操作符也可能触发缓冲区溢出，或者在 fprintf 等文件格式化函数中使用时，它可能生成比预期大得多的输出。
