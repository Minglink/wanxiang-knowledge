# CWE-1322: 在单线程非阻塞上下文中使用了阻塞代码

## 缺陷定义

产品使用依赖于单线程进程来实现可扩展性等功能的非阻塞模型，但包含在调用时可能会阻塞的代码。

## 机制与扩展说明

当攻击者能够直接调用阻塞代码，或者阻塞代码会受到可被攻击者影响的环境条件影响时，可能会导致代码出现意外的挂起或冻结，从而导致拒绝服务。阻塞代码的示例可能包括高开销的计算或调用阻塞库函数，例如执行排他性文件操作或需要成功网络操作的调用。
由于多线程模型的限制，单线程模型被用于克服由使用大量线程引起的资源约束。在这种模型中，所有代码通常应该是非阻塞的。如果调用了阻塞代码，事件循环将实际上被停止，这可能是不可取的或危险的。此类模型被用于 Python asyncio、Vert.x 和 Node.js，或其他自定义的事件循环代码中。

## 预防与缓解措施

缓解措施
实施
一般来说，阻塞调用应被替换为可异步使用的非阻塞替代方案。高开销的计算应移交给工作线程，不过具体正确的方法取决于所使用的框架。

对于高开销计算，考虑将其分解为多个较小的计算任务。请参考所用框架的文档以获取指导。

Use of Blocking Code in Single-threaded, Non-blocking Context

The product uses a non-blocking model that relies on a single threaded process
			for features such as scalability, but it contains code that can block when it is invoked.
