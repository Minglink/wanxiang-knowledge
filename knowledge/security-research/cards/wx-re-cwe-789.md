# CWE-789: 内存分配值过大

## 缺陷定义

产品基于未经信任的过大尺寸值分配内存，但未确保该尺寸在预期限制范围内，从而允许分配任意数量的内存。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
DoS: 资源消耗（内存）
范围：可用性
不对内存分配进行控制可能导致对过量系统内存的请求，进而可能因内存不足而导致应用程序崩溃，或消耗系统的大量内存。

## 预防与缓解措施

阶段
缓解措施
实现；架构与设计
对任何影响内存分配量的数值执行充分的输入验证。制定适当的策略来处理超出限制的请求，并考虑支持配置选项，以便管理员在必要时可以扩展可使用的内存量。
运营
使用系统提供的资源限制来运行程序。这可能仍会导致程序崩溃或退出，但对系统其余部分的影响将降至最低。

## 补充说明与边界

关系
此弱点可能与整数溢出 (
CWE-190
) 密切相关。整数溢出攻击侧重于提供一个极大的数字来触发溢出，导致分配的内存少于预期。通过提供一个不触发整数溢出的大值，攻击者仍然可以导致分配过量的内存。
适用平台
不受控制的内存分配在许多语言中都是可能的，例如 Perl 中的动态数组分配或 Java 中集合的初始大小参数。然而，像 C 和 C++ 这样程序员可以更直接地控制内存管理的语言更容易受到此弱点的影响。

## 官方英文定义（核对锚点）

Memory Allocation with Excessive Size Value

The product allocates memory based on an untrusted, large size value, but it does not ensure that the size is within expected limits, allowing arbitrary amounts of memory to be allocated.
