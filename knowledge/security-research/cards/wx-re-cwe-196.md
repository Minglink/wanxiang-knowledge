# CWE-196: 无符号到有符号转换错误

## 缺陷定义

产品使用无符号原始类型并执行到有符号原始类型的强制转换，如果无符号原始类型的值不能使用有符号原始类型表示，这可能会产生意外的值。

## 机制与扩展说明

尽管无符号到有符号的转换问题不如有符号到无符号的转换常见，但它可能是导致危险缓冲区下溢（buffer underwrite）状况的完美前兆。这些状况允许攻击者访问在正常缓冲区溢出条件下本无法访问的栈空间。当大的无符号值被强制转换为有符号值，并随后被用作缓冲区索引或进行指针运算时，经常会发生缓冲区下溢。

## 预防与缓解措施

阶段
缓解措施
需求
选择一种不会出现这些转换缺陷的编程语言。
架构与设计
设计对象访问函数以隐式检查值的大小是否有效。确保所有将被用作大小的函数在使用前都经过检查。如果语言允许，抛出异常而不是使用带内（in-band）错误。
实施
检查所有函数的返回值。注意隐式转换，并尽可能为表示大小的变量使用无符号类型。

## 官方英文定义（核对锚点）

Unsigned to Signed Conversion Error

The product uses an unsigned primitive and performs a cast to a signed primitive, which can produce an unexpected value if the value of the unsigned primitive can not be represented using a signed primitive.
