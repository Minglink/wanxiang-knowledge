# CWE-41: 路径等价性解析不当

## 缺陷定义

产品易受路径等价引起的文件系统内容泄露影响。路径等价涉及在文件和目录名中使用特殊字符。相关的操作旨在为同一个对象生成多个名称。

## 机制与扩展说明

路径等价性通常被利用来规避那些使用不完整文件名或文件路径表示法所设定的访问控制。这与路径遍历不同，路径遍历是为了生成指向不同对象的名称而进行的操作。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。

详细信息
读取文件或目录；修改文件或目录；绕过保护机制
范围：机密性、完整性、访问控制
攻击者可能能够遍历文件系统至非预期的位置，并读取或覆盖非预期文件的内容。如果这些文件被用于安全机制，攻击者可能能够绕过该机制。

策略：
输入验证
假设所有输入都是恶意的。采用“接受已知良好”的输入验证策略，即使用严格符合规范的可接受输入列表。拒绝任何不严格符合规范的输入，或将其转换为符合规范的内容。
在执行输入验证时，考虑所有潜在相关的属性，包括长度、输入类型、可接受值的全部范围、缺失或额外的输入、语法、跨相关字段的一致性以及对业务规则的符合性。作为业务规则逻辑的一个例子，“boat”在语法上可能是有效的，因为它只包含字母数字字符，但如果输入只预期包含“red”或“blue”等颜色，则它无效。
不要仅仅依赖查找恶意或畸形输入。这很可能会遗漏至少一种不受欢迎的输入，尤其是当代码环境发生变化时。这可能给攻击者留出绕过预期验证的空间。不过，黑名单对于检测潜在攻击或确定哪些输入由于严重畸形而应被直接拒绝是有用的。

输出编码
使用并指定下游组件读取输出时可以处理的输出编码。常见的编码包括 ISO-8859-1、UTF-7 和 UTF-8。当未指定编码时，下游组件可能会选择不同的编码，要么通过假设默认编码，要么自动推断正在使用的编码，这可能会出错。当编码不一致时，下游组件可能会将某些字符或字节序列视为特殊字符，即使它们在原始编码中并非特殊字符。攻击者可能会利用这种差异发起注入攻击；甚至可以绕过那些假设下游组件使用原始编码的防护机制。

在验证之前，输入应解码并规范化为应用程序当前内部的表示形式（
CWE-180

CWE-174

## 官方英文定义（核对锚点）

Improper Resolution of Path Equivalence

The product is vulnerable to file system contents disclosure through path equivalence. Path equivalence involves the use of special characters in file and directory names. The associated manipulations are intended to generate multiple names for the same object.
