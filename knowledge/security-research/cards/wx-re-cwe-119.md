# CWE-119：内存缓冲区边界内的操作限制不当

## 缺陷定义

产品对内存缓冲区执行操作时，从缓冲区预期边界之外的内存位置进行读取或写入。这可能导致对意料之外的内存位置进行读写操作，这些位置可能关联到其他变量、数据结构或内部程序数据。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
执行未经授权的代码或命令；修改内存
范围：完整性、机密性、可用性
如果攻击者可以有效控制可访问的内存，则可能像标准缓冲区溢出一样执行任意代码。如果攻击者可以覆盖一个指针大小的内存（通常为 32 或 64 位），他们可以通过将函数指针重定向到自己的恶意代码来改变预期的控制流。即使攻击者只能修改单个字节，也可能实现任意代码执行。有时这是因为同一个问题可以被反复利用以达到同样的效果。另一些时候是因为攻击者可以覆盖与安全相关的应用程序特定数据——例如指示用户是否为管理员的标志。
读取内存；DoS：崩溃、退出或重启；DoS：资源消耗（CPU）；DoS：资源消耗（内存）
范围：可用性，机密性
越界内存访问极有可能导致相关内存甚至指令的损坏，并可能导致程序崩溃。还可能引发导致可用性丧失的其他攻击，包括使程序进入无限循环。
读取内存
范围：机密性
在越界读取的情况下，攻击者可能访问敏感信息。如果敏感信息包含系统详细信息（例如当前缓冲区在内存中的位置），这些知识可用于策划进一步的攻击，并可能导致更严重的后果。

## 预防与缓解措施

阶段
缓解措施
需求
策略：
语言选择
使用一种不允许此弱点发生或提供使此弱点更容易避免的结构的语言。
例如，许多自行管理内存的语言，如 Java 和 Perl，不易受到缓冲区溢出的影响。其他语言，如 Ada 和 C#，通常提供溢出保护，但程序员可以禁用该保护。
请注意，即使语言本身在理论上是安全的，语言到原生代码的接口可能仍然容易受到溢出的影响。
架构与设计
策略：
库或框架
使用经过审查的库或框架，该库或框架不允许此弱点发生，或提供使此弱点更容易避免的结构。
示例包括 Messier 和 Viega 的安全 C 字符串库 (SafeStr) [
REF-57
]，以及微软的 Strsafe.h 库 [
REF-56
]。这些库提供了更安全的易溢出字符串处理函数版本。
注意：
这不是一个完整的解决方案，因为许多缓冲区溢出与字符串无关。
操作；构建与编译
策略：
环境强化
使用某些编译器或编译器扩展提供的自动缓冲区溢出检测机制。示例包括：Microsoft Visual Studio 的 /GS 标志、Fedora/Red Hat 的 FORTIFY_SOURCE GCC 标志、StackGuard 和 ProPolice，它们提供各种机制，包括基于金丝雀（canary）的检测和范围/索引检查。
来自 D3FEND 的 D3-SFCV（栈帧金丝雀验证）[
REF-1334
] 详细讨论了基于金丝雀（canary）的检测。
有效性：纵深防御
注意：
这不一定是一个完整的解决方案，因为这些机制只能检测某些类型的溢出。此外，结果仍然是拒绝服务，因为典型的响应是退出应用程序。
实施
在分配和管理应用程序内存时，请考虑遵循以下规则
仔细检查缓冲区是否确实如指定的那么大。
使用接受要复制的字节数的函数（如 strncpy()）时，请注意，如果目标缓冲区大小等于源缓冲区大小，它可能不会 NULL 终止字符串。
如果在循环中访问缓冲区，请检查缓冲区边界，并确保不会写入超出分配空间的内容。
必要时，在将所有输入字符串传递给复制和连接函数之前，将其截断为合理的长度。
操作；构建与编译
策略：
环境强化
使用在内存中随机排列程序可执行文件和库位置的功能或扩展来运行或编译软件。由于这使得地址不可预测，它可以防止攻击者可靠地跳转到可利用的代码。
示例包括地址空间布局随机化 (ASLR) [
REF-58
] [
REF-60
] 和位置无关可执行文件 (PIE) [
REF-64
]。如果导入模块的默认内存地址与其他模块冲突，可以使用随机生成的地址以“重定位”（Windows 称“rebasing”）和“预链接”（Linux 称“prelinking”）的方式进行重新对齐 [
REF-1332
]。ASLR 不能与预链接结合使用，因为这需要在运行时重定位库，从而破坏了预链接的初衷。
有关这些技术的更多信息，请参阅 D3FEND 的 D3-SAOR（段地址偏移随机化）[
REF-1335
]。
有效性：纵深防御
注意：
这些技术不能提供完整的解决方案。例如，漏洞利用经常使用会泄露内存地址的漏洞，以最大限度地提高代码执行的可靠性 [
REF-1337
]。研究还表明，侧信道攻击可以绕过 ASLR [
REF-1333
]。
运营
策略：
环境强化
使用提供数据执行保护 (DEP) 的 CPU 和操作系统（使用硬件 NX 或 XD 位），或者在软件中模拟此功能的等效技术，如 PaX [
REF-60
] [
REF-61
]。这些技术确保执行的任何指令仅位于代码段内的内存地址。
有关这些技术的更多信息，请参阅 D3FEND 的 D3-PSEP（进程段执行预防）[
REF-1336
]。
有效性：纵深防御
注：
这不是一个完整的解决方案，因为缓冲区溢出可能被用来覆盖附近的变量，以危险的方式修改软件状态。此外，它不能用于需要自修改代码的情况。最后，攻击仍然可能导致拒绝服务，因为典型的响应是退出应用程序。
实施
用支持长度参数的类似函数替换无界复制函数，例如用 strncpy 替换 strcpy。如果它们不可用，请创建它们。
有效性：中等
注意：
此方法仍然容易受到计算错误的影响，包括差一错误 (
CWE-193
) 和缓冲区长度计算错误 (
CWE-131
) 等问题。

## 背景机制

某些语言允许直接寻址内存位置，并且不会自动确保这些位置对于正在引用的内存缓冲区是有效的。

## 补充说明与边界

适用平台
在任何没有内存管理支持的编程语言中，都有可能尝试在内存缓冲区边界之外进行操作，但后果会根据语言、平台和芯片架构的不同而有很大差异。

## 官方英文定义（核对锚点）

Improper Restriction of Operations within the Bounds of a Memory Buffer

The product performs operations on a memory buffer, but it reads from or writes to a memory location outside the buffer's intended boundary. This may result in read or write operations on unexpected memory locations that could be linked to other variables, data structures, or internal program data.
