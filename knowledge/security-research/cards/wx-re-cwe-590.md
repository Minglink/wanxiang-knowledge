# CWE-590: 释放非堆内存

## 缺陷定义

产品对未通过 malloc()、calloc() 或 realloc() 等相关堆分配函数分配的内存指针调用了 free()。

## 机制与扩展说明

当对无效指针调用 free() 时，程序的内存管理数据结构可能会损坏。这种损坏可能导致程序崩溃，或者在某些情况下，攻击者可能能够利用 free() 对可控内存位置进行操作，从而修改关键程序变量或执行代码。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
执行未经授权的代码或命令；修改内存
范围：完整性、机密性、可用性
通过“任意地址写入”（write-what-where）原语，存在以受漏洞程序权限执行任意代码的可能性。如果保存用户信息内存的指针被释放，恶意用户将能够在内存中的任何位置写入 4 个字节。

## 预防与缓解措施

阶段
缓解措施
实施
仅释放之前调用过 malloc 的指针。这是推荐的解决方案。跟踪哪些指针指向有效内存块的起始位置，并确保每个指针仅被释放一次。
实施
在释放指针之前，程序员应确保该指针先前是在堆上分配的，并且该内存归程序员所有。释放未分配的指针会导致程序出现未定义的行为。
架构与设计
策略：
库或框架
使用经过审查的库或框架，该库或框架不允许此弱点发生，或提供使此弱点更容易避免的结构。
例如，Linux 中的 glibc 提供了防止释放无效指针的保护机制。
架构与设计
使用提供内存分配和释放抽象的语言。

## 官方英文定义（核对锚点）

Free of Memory not on the Heap

The product calls free() on a pointer to memory that was not allocated using associated heap allocation functions such as malloc(), calloc(), or realloc().
