# CWE-428: 未引用的搜索路径或元素

## 缺陷定义

产品使用的搜索路径包含一个未引用的元素，且该元素包含空格或其他分隔符。这可能导致产品访问父路径中的资源。

## 机制与扩展说明

如果恶意个人可以访问文件系统，他们可以通过插入名为 "C:\Program.exe" 的文件，诱使使用 WinExec 的特权程序运行该文件，从而实现权限提升。

## 预防与缓解措施

缓解措施
实施
在系统上执行程序之前，请正确引用完整的搜索路径。
实施
策略：
输入验证
假设所有输入都是恶意的。采用“接受已知良好”的输入验证策略，即使用严格符合规范的可接受输入列表。拒绝任何不严格符合规范的输入，或将其转换为符合规范的内容。
在执行输入验证时，考虑所有潜在相关的属性，包括长度、输入类型、可接受值的全部范围、缺失或额外的输入、语法、跨相关字段的一致性以及对业务规则的符合性。作为业务规则逻辑的一个例子，“boat”在语法上可能是有效的，因为它只包含字母数字字符，但如果输入只预期包含“red”或“blue”等颜色，则它无效。
不要仅仅依赖查找恶意或畸形输入。这很可能会遗漏至少一种不受欢迎的输入，尤其是当代码环境发生变化时。这可能给攻击者留出绕过预期验证的空间。不过，黑名单对于检测潜在攻击或确定哪些输入由于严重畸形而应被直接拒绝是有用的。
实施
策略：
输入验证
在验证之前，输入应解码并规范化为应用程序当前内部的表示形式（
CWE-180
）。确保应用程序不会对同一输入进行两次解码（
CWE-174
）。此类错误可能被用于通过在检查后引入危险输入来绕过允许列表验证方案。

## 补充说明与边界

适用平台
此弱点可能适用于任何支持文件名中包含空格的操作系统，尤其是像 Windows 这样使用户容易在文件名或文件夹中插入空格的任何操作系统。虽然 Unix 在技术上支持空格，但通常会避免这种做法。
维护
此弱点主要涉及缺乏引用，而这并非
CWE-116
中明确指出的部分。
CWE-116
也从结构化消息的角度描述了输出，但文件名或搜索路径的生成（如本弱点所述）可能不被视为结构化消息。
另一个复杂因素是与控制域的关系。与本质上涉及对控制域定义进行控制的不可信搜索路径 (
CWE-426
) 不同，此条目涉及一个固定的控制域，其中部分领域可能处于攻击者的控制之下。这在
CWE-668
或
CWE-610
下并不完全契合，这表明控制域模型需要增强或澄清。

## 官方英文定义（核对锚点）

Unquoted Search Path or Element

The product uses a search path that contains an unquoted element, in which the element contains whitespace or other separators. This can cause the product to access resources in a parent path.
