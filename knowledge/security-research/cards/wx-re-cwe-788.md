# CWE-788：缓冲区末尾之后的内存位置访问

## 缺陷定义

产品使用引用缓冲区末尾之后内存位置的索引或指针来读取或写入缓冲区。

## 机制与扩展说明

这通常发生在指针或其索引递增到缓冲区之后的位置时；或者当指针算术运算的结果指向缓冲区之后的位置时。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
读取内存
范围：机密性
对于越界读取，攻击者可能获得敏感信息的访问权限。如果敏感信息包含系统详细信息（例如当前缓冲区在内存中的位置），这些信息可用于实施进一步的攻击，并可能导致更严重的后果。
修改内存；拒绝服务 (DoS)：崩溃、退出或重启
范围：完整性、可用性
越界内存访问极有可能导致相关内存甚至指令的损坏，并可能导致程序崩溃。还可能引发导致可用性丧失的其他攻击，包括使程序进入无限循环。
修改内存；执行未经授权的代码或命令
范围：完整性
如果攻击者可以有效控制可访问的内存，则可能像标准缓冲区溢出一样执行任意代码。如果攻击者能够覆盖指针大小的内存（通常为 32 或 64 位），他们就可以将函数指针重定向到他们自己的恶意代码。即使攻击者只能修改单个字节，执行任意代码也是可能的。有时这是因为同一个问题可以被反复利用以达到相同的效果。另一些时候，这是因为攻击者可以覆盖与应用程序相关的安全关键数据——例如指示用户是否为管理员的标志。

## 官方英文定义（核对锚点）

Access of Memory Location After End of Buffer

The product reads or writes to a buffer using an index or pointer that references a memory location after the end of the buffer.
