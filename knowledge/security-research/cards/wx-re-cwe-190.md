# CWE-190: 整数溢出或回绕

## 缺陷定义

产品执行的计算在逻辑假设结果值总是大于原始值时，可能会产生整数溢出或回绕。当一个整数值增加到太大而无法存储在相关的表示形式中时，就会发生这种情况。此时，该值可能会变成一个非常小或负数。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
DoS: 崩溃、退出或重启；DoS: 资源消耗（内存）；DoS: 不稳定性
范围：可用性
这种弱点通常会导致未定义的行为，进而导致崩溃。当计算结果用于资源分配时，该弱点可能导致分配过量（或过少）的资源，如果产品请求的资源超过了可提供的限额，可能会导致崩溃。
修改内存
范围：完整性
如果所涉及的值对数据（相对于流程）很重要，则会发生简单的数据损坏。此外，如果溢出/回绕导致了其他条件（如缓冲区溢出），则可能发生进一步的内存损坏。
执行未经授权的代码或命令；绕过保护机制
范围：机密性、可用性、访问控制
这种弱点有时会触发缓冲区溢出，从而被用于执行任意代码。这通常超出了产品隐含安全策略的范围。
修改执行逻辑；DoS: 崩溃、退出或重启；DoS: 资源消耗（CPU）
范围: 可用性, 其他
如果溢出/回绕发生在循环索引变量中，可能会导致循环在错误的时间终止——过早、过晚，或者根本不终止（即无限循环）。如果迭代次数过多，某些循环可能会消耗过多的资源（如内存、文件句柄等），从而可能导致崩溃或其他 DoS。
绕过保护机制
范围: 访问控制
如果整数值被用于安全关键决策（如计算配额或分配限制），整数溢出可被利用来导致错误的安全决策。

## 补充说明与边界

关系
整数溢出可能是缓冲区溢出的主要原因，因为它们会导致分配的内存少于预期。
术语
“整数溢出”有时被用来涵盖多种类型的错误，包括符号错误，或涉及操作整数数据类型而不是字符的缓冲区溢出。部分混淆源于这样一个事实：在有符号上下文中，0xffffffff 等于 -1。其他混淆也源于整数溢出在链中所扮演的角色。
“回绕”是一种定义明确的标准行为，遵循特定规则，规定了当预期的数值太大或太小而无法表示时如何处理这些情况，正如 C11 等标准中规定的那样。
“溢出”有时与“回绕”混淆，但通常指非标准或未定义的行为。
“溢出”术语有时用于表示超出最大值或最小值的情况，但其他人可能仅使用“溢出”表示超出最大值，而使用“下溢”表示超出最小值。
有些人使用“溢出”来表示任何超出可表示范围的值——无论是大于最大值，还是小于最小值——但 CWE 将预期结果小于最小值的情况称为“下溢”。
有关术语歧义的更多解释，请参阅 [
REF-1440
]。
其他
虽然在某些情况下逻辑可能有意依赖回绕（例如计时器或计数器中的模运算），但如果回绕是出乎意料的，它可能会产生安全后果。如果可以使用用户提供的输入触发整数溢出，则尤其如此。

## 官方英文定义（核对锚点）

Integer Overflow or Wraparound

The product performs a calculation that can
         produce an integer overflow or wraparound when the logic
         assumes that the resulting value will always be larger than
         the original value. This occurs when an integer value is
         incremented to a value that is too large to store in the
         associated representation. When this occurs, the value may
         become a very small or negative number.
