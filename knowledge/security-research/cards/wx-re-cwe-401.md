# CWE-401: 有效生命周期结束后未释放内存

## 缺陷定义

产品在分配的内存使用完毕后，未能充分追踪并释放该内存，导致该内存无法被重新分配和重复利用。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
DoS：崩溃、退出或重启；DoS：不稳定；DoS：资源消耗（CPU）；DoS：资源消耗（内存）
范围：可用性
大多数内存泄漏会导致一般性的产品可靠性问题。但如果攻击者能够有意触发内存泄漏，他们可能发起拒绝服务攻击（通过使程序崩溃或挂起），或者利用因内存不足而产生的意外程序行为。
降低性能
范围：其他

## 预防与缓解措施

阶段
缓解措施
实施
策略：
库或框架
选择提供自动内存管理，或使手动内存管理不易出错的语言或工具。
例如，Linux 中的 glibc 提供了防止释放无效指针的保护机制。
在使用 Xcode 开发 OS X 或 iOS 应用时，启用自动引用计数 (ARC) [
REF-391
]。
在 C++ 编程中，为了正确且一致地管理内存，可以考虑使用智能指针类，例如 std::auto_ptr（由 ISO/IEC 14882:2003 定义）、std::shared_ptr 和 std::unique_ptr（由 C++ 标准的后续修订版本指定，非正式称为 C++ 1x），或使用 Boost 等等效方案。
架构与设计
使用抽象库来封装有风险的 API。但这并非完整的解决方案。
架构与设计；构建与编译
考虑使用 Boehm-Demers-Weiser 垃圾回收器 (bdwgc)，它有助于避免泄漏。
有效性：中等
注意：
这不是一个完整的解决方案，因为它并非 100% 有效。

模糊测试 (Fuzzing) 是一种强大的技术，用于生成大量多样化的输入（随机或按算法生成），并使用这些输入动态调用代码。即使使用随机输入，它也经常能产生意想不到的结果，如崩溃、内存损坏或资源消耗。模糊测试有效地生成了可重复的测试用例，明确指出错误，从而帮助开发人员诊断问题。

## 官方英文定义（核对锚点）

Missing Release of Memory after Effective Lifetime

The product does not sufficiently track and release allocated memory after it has been used, making the memory unavailable for reallocation and reuse.
