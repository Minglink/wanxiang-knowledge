# CWE-120: 缓冲区复制时未检查输入大小（“经典缓冲区溢出”）

## 缺陷定义

产品在将输入缓冲区复制到输出缓冲区时，未验证输入缓冲区的大小是否小于输出缓冲区的大小。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
修改内存；执行未经授权的代码或命令
范围：完整性、机密性、可用性
缓冲区溢出通常可用于执行任意代码，这通常超出了产品隐含安全策略的范围。这往往可以用来破坏任何其他安全服务。
修改内存；DoS：崩溃、退出或重启；DoS：资源消耗 (CPU)
范围：可用性
缓冲区溢出通常会导致崩溃。也可能出现导致可用性丧失的其他攻击，包括使产品进入无限循环。

## 预防与缓解措施

阶段
缓解措施
需求
策略：
语言选择
使用一种不允许此弱点发生或提供使此弱点更容易避免的结构的语言。
例如，许多自行管理内存的语言，如 Java 和 Perl，不易受到缓冲区溢出的影响。其他语言，如 Ada 和 C#，通常提供溢出保护，但程序员可以禁用该保护。
请注意，即使语言本身在理论上是安全的，语言到原生代码的接口可能仍然容易受到溢出的影响。
架构与设计
策略：
库或框架
使用经过审查的库或框架，该库或框架不允许此弱点发生，或提供使此弱点更容易避免的结构。
示例包括 Messier 和 Viega 的安全 C 字符串库 (SafeStr) [
REF-57
]，以及微软的 Strsafe.h 库 [
REF-56
]。这些库提供了易于溢出的字符串处理函数的更安全版本。
注意：
这不是一个完整的解决方案，因为许多缓冲区溢出与字符串无关。
操作；构建与编译
策略：
环境强化
使用某些编译器或编译器扩展提供的自动缓冲区溢出检测机制。示例包括：Microsoft Visual Studio 的 /GS 标志、Fedora/Red Hat 的 FORTIFY_SOURCE GCC 标志、StackGuard 和 ProPolice，它们提供各种机制，包括基于金丝雀（canary）的检测和范围/索引检查。
来自 D3FEND 的 D3-SFCV（栈帧金丝雀验证）[
REF-1334
] 详细讨论了基于金丝雀（canary）的检测方法。
有效性：纵深防御
注意：
这不一定是一个完整的解决方案，因为这些机制只能检测某些类型的溢出。此外，结果仍然是拒绝服务，因为典型的响应是退出应用程序。
实施
在分配和管理应用程序内存时，请考虑遵循以下规则
仔细检查您的缓冲区是否与您指定的容量一样大。
使用接受要复制的字节数的函数（如 strncpy()）时，请注意，如果目标缓冲区大小等于源缓冲区大小，它可能不会 NULL 终止字符串。
如果在循环中访问缓冲区，请检查缓冲区边界，并确保不会写入超出分配空间的内容。
必要时，在将所有输入字符串传递给复制和连接函数之前，将其截断为合理的长度。
实施
策略：
输入验证
假设所有输入都是恶意的。采用“接受已知良好”的输入验证策略，即使用严格符合规范的可接受输入列表。拒绝任何不严格符合规范的输入，或将其转换为符合规范的内容。
在执行输入验证时，考虑所有潜在相关的属性，包括长度、输入类型、可接受值的全部范围、缺失或额外的输入、语法、跨相关字段的一致性以及对业务规则的符合性。作为业务规则逻辑的一个例子，“boat”在语法上可能是有效的，因为它只包含字母数字字符，但如果输入只预期包含“red”或“blue”等颜色，则它无效。
不要仅仅依赖查找恶意或畸形输入。这很可能会遗漏至少一种不受欢迎的输入，尤其是当代码环境发生变化时。这可能给攻击者留出绕过预期验证的空间。不过，黑名单对于检测潜在攻击或确定哪些输入由于严重畸形而应被直接拒绝是有用的。
架构与设计
对于在客户端执行的任何安全检查，请确保在服务器端重复这些检查，以避免
CWE-602
。攻击者可以通过在检查执行后修改值，或修改客户端以完全移除客户端检查来绕过这些检查。随后，这些被修改的值将被提交到服务器。
操作；构建与编译
策略：
环境强化
使用在内存中随机排列程序可执行文件和库位置的功能或扩展来运行或编译软件。由于这使得地址不可预测，它可以防止攻击者可靠地跳转到可利用的代码。
示例包括地址空间布局随机化 (ASLR) [
REF-58
] [
REF-60
] 和位置无关可执行文件 (PIE) [
REF-64
]。如果导入模块的默认内存地址与其他模块冲突，可以使用随机生成的地址以“重定向”（Windows）和“预链接”（Linux）[
REF-1332
] 的方式对这些模块进行重新对齐。库的 ASLR 不能与预链接结合使用，因为它需要在运行时重新定位库，从而抵消了预链接的全部目的。
有关这些技术的更多信息，请参阅 D3FEND 的 D3-SAOR（段地址偏移随机化）[
REF-1335
]。
有效性：纵深防御
注意:
这些技术并不能提供完整的解决方案。例如，漏洞利用经常使用披露内存地址的错误来最大限度地提高代码执行的可靠性 [
REF-1337
]。研究还表明，侧信道攻击可以绕过 ASLR [
REF-1333
]。
运营
策略：
环境强化
使用提供数据执行保护（使用硬件 NX 或 XD 位）的 CPU 和操作系统，或使用在软件中模拟此功能的等效技术，例如 PaX [
REF-60
] [
REF-61
]。这些技术确保执行的任何指令都仅位于属于代码段的内存地址中。
有关这些技术的更多信息，请参阅 D3FEND 的 D3-PSEP（进程段执行预防）[
REF-1336
]。
有效性：纵深防御
注：
这不是一个完整的解决方案，因为缓冲区溢出可能被用来覆盖附近的变量，以危险的方式修改软件状态。此外，它不能用于需要自修改代码的情况。最后，攻击仍然可能导致拒绝服务，因为典型的响应是退出应用程序。
构建与编译；运行
迄今为止，编译器或操作系统级别的大多数缓解技术仅解决了缓冲区溢出问题的一个子集，即使针对该子集也很少提供完全保护。实施策略以增加攻击者的工作负载是一种好的做法，例如让攻击者猜测一个在每次程序执行时都会改变的未知值。
实施
用支持长度参数的类似函数替换无界复制函数，例如用 strncpy 替换 strcpy。如果它们不可用，请创建它们。
有效性：中等
注意：
此方法仍然容易受到计算错误的影响，包括差一错误 (
CWE-193
) 和缓冲区长度计算错误 (
CWE-131
) 等问题。
架构与设计
策略：
通过转换执行
当可接受对象（如文件名或 URL）的集合有限或已知时，创建从一组固定输入值（如数字 ID）到实际文件名或 URL 的映射，并拒绝所有其他输入。
架构与设计；运维
策略：
环境强化
以完成必要任务所需的最低权限运行代码 [
REF-76
]。如果可能，创建仅用于单个任务且权限受限的隔离帐户。这样，成功的攻击就不会立即让攻击者访问软件的其余部分或其环境。例如，数据库应用程序很少需要以数据库管理员身份运行，特别是在日常操作中。
架构与设计；运维
策略：
沙盒或囚笼
在“囚笼 (jail)”或类似的沙盒环境中运行代码，该环境在进程和操作系统之间强制执行严格的边界。这可以有效地限制在特定目录中可以访问哪些文件，或者软件可以执行哪些命令。
操作系统级别的示例包括 Unix chroot 囚笼、AppArmor 和 SELinux。通常，受管代码可能会提供一些保护。例如，Java SecurityManager 中的 java.io.FilePermission 允许软件对文件操作指定限制。
这可能不是一个可行的解决方案，并且它仅将影响限制在操作系统层面；应用程序的其余部分仍可能面临被妥协的风险。
小心避免
CWE-243
以及与囚笼相关的其他弱点。
有效性：有限
注：
此缓解措施的有效性取决于所使用的特定沙盒或囚笼的防护能力，可能仅有助于减小攻击范围，例如限制攻击者使用某些系统调用或限制可访问的文件系统部分。

## 补充说明与边界

关系
在代码层面，基于栈和基于堆的溢出没有显著差异，因此通常不需要区分它们。从攻击者的角度来看，它们可能截然不同，因为利用它们需要不同的技术。
术语
关于“缓冲区溢出”一词存在严重的不一致，它可能有多种解释和用法。许多人将其理解为“写入超出缓冲区末尾”。其他人则将其理解为“写入超出缓冲区末尾，或在缓冲区开头之前”。还有一些人可能会将“读取”也包含在该术语中。
其他
当产品试图在缓冲区中放入超出其容纳能力的数据，或者当它试图在缓冲区边界之外的内存区域中放入数据时，就会出现缓冲区溢出情况。最简单的错误类型，也是缓冲区溢出的最常见原因，是“经典”情况，即产品在不限制复制数据量的情况下复制缓冲区。存在其他变体，但经典溢出的存在强烈表明程序员甚至没有考虑最基本的安全保护。

## 官方英文定义（核对锚点）

Buffer Copy without Checking Size of Input ('Classic Buffer Overflow')

The product copies an input buffer to an output buffer without verifying that the size of the input buffer is less than the size of the output buffer.

抽象级别：Base；上游状态：Incomplete。这是弱点机制条目，不等同于某一具体 CVE，也不证明某个程序已存在该缺陷。正文中未提供的检测或修复条件不能自行视为已满足。
