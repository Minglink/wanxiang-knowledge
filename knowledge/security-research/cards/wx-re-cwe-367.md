# CWE-367: 检查时机与使用时机 (TOCTOU) 竞争条件

## 缺陷定义

产品在资源使用前会检查其状态，但在检查与使用之间，资源的状态可能会发生改变，从而导致检查结果失效。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
改变执行逻辑；意外状态
范围: 完整性，其他
攻击者可以获得对原本未授权资源的访问权限。
修改应用程序数据；修改文件或目录；修改内存；其他
范围: 完整性，其他
此类竞争条件可用于获取对特定用户通常不可读或不可写资源的读写访问权限。
其他
范围: 完整性，其他
所涉及的资源或其他资源（通过受损资源）可能会被恶意用户以非预期的方式修改。

范围：不可抵赖性
如果文件或其他资源以这种方式（而非合法方式）被写入，则该活动可能不会被记录日志。
其他
范围：不可否认性，其他
在某些情况下，可以删除恶意用户原本无法访问的文件，例如日志文件。
非预期状态
范围：其他
当资源处于非预期状态时，产品可能会执行无效操作。

## 预防与缓解措施

阶段
缓解措施
实施
针对 TOCTOU 漏洞最基本的建议是不要在“使用”前进行“检查”。这并不能解决在状态和身份无法保证的资源上执行函数这一根本问题，但它有助于限制由检查带来的虚假安全感。
实施
当被修改的文件归当前用户和组所有时，在执行此语句时将有效 gid 和 uid 设置为当前用户和组。
架构与设计
限制来自多个进程的文件操作交替执行。
实现；架构与设计
如果您无法原子地执行操作，且必须在多个进程或线程之间共享资源访问权限，请尝试限制资源在检查与使用之间的时间间隔（CPU 周期）。这不能解决问题，但会增加攻击成功的难度。
实施
在使用调用之后重新检查资源，以验证操作是否已适当地执行。
架构与设计
确保可以使用某种环境锁定机制来有效保护资源。
实施
确保在检查之前（而不是之后）进行锁定，使得检查时的资源与使用时的资源保持一致。

## 补充说明与边界

关系
TOCTOU 问题并不总是涉及符号链接，也不是每个符号链接问题都是 TOCTOU 问题。
研究差距
非符号链接的 TOCTOU 问题虽然报告频率不高，但很可能发生在试图确保安全的代码中。

## 官方英文定义（核对锚点）

Time-of-check Time-of-use (TOCTOU) Race Condition

The product checks the state of a resource before using that resource, but the resource's state can change between the check and the use in a way that invalidates the results of the check.
