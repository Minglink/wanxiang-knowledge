# CWE-828：信号处理程序包含非异步安全的功能

## 缺陷定义

产品定义的信号处理程序包含非异步安全（asynchronous-safe）的代码序列，即该功能不是可重入的，或者它可能会被中断。

## 机制与扩展说明

这可能导致意外的系统状态，并根据上下文产生多种潜在后果，包括拒绝服务和代码执行。
信号处理程序通常旨在中断程序的正常功能，甚至中断其他信号，以通知进程发生了某个事件。当信号处理程序使用全局变量或静态变量，或者调用最终依赖于此类状态或其相关元数据的功能时，它可能会破坏正常功能正在使用的系统状态。这可能使程序受到竞争条件或其他弱点的影响，从而允许攻击者导致程序状态损坏。虽然拒绝服务是常见的后果，但在某些情况下，此弱点可被利用进行代码执行。
有几种不同的场景会引入此问题：
在处理程序内部调用非可重入函数。一个例子是 malloc()，它在管理内存时会修改内部全局变量。实际上，很少有函数是可重入的。
代码序列（不一定是函数调用）包含对全局变量或相关元数据/结构的非原子使用，这些变量或结构可被程序的其他功能（包括其他信号处理程序）访问。通常，同一个函数被注册用于处理多个信号。
信号处理程序函数本应最多运行一次，但实际上可能被多次调用。这可能是由于重复发送相同的信号，或由于发送了具有相同处理程序函数的不同信号（
CWE-831
）所致。
请注意，在某些环境或上下文中，信号处理程序本身也可能被中断。
如果信号处理程序和产品的正常行为必须对同一组状态变量进行操作，并且在正常执行修改这些变量的过程中接收到信号，那么在信号处理程序执行期间，变量可能处于不正确或损坏的状态，并且在返回时可能仍然是不正确或损坏的。

## 预防与缓解措施

阶段
缓解措施
实现；架构与设计
消除信号处理程序内部对非可重入功能的使用。这包括将所有非可重入的库调用替换为可重入调用。
注意：这并不总是可能的，可能需要重写甚至重新设计产品的大部分内容。有时可能没有可重入的安全库替代方案。有时系统状态与信号处理程序之间的非可重入交互是设计所必需的。
有效性：高
实施
如果必须在信号处理程序中使用非可重入功能，请务必适当地阻塞或屏蔽信号。这包括在信号处理程序本身内阻塞其他也可能利用该功能的信号。它还包括在产品的正常行为访问或修改该功能时，阻塞所有依赖于该功能的信号。

## 官方英文定义（核对锚点）

Signal Handler with Functionality that is not Asynchronous-Safe

The product defines a signal handler that contains code sequences that are not asynchronous-safe, i.e., the functionality is not reentrant, or it can be interrupted.
