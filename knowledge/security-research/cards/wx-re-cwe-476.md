# CWE-476: NULL 指针解引用

## 缺陷定义

产品对一个期望有效但实际上为 NULL 的指针进行了解引用。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
DoS：崩溃、退出或重启
范围：可用性
除非（在某些平台上）实现了异常处理，否则 NULL 指针解引用通常会导致进程失败。即使使用了异常处理，也很难将软件恢复到安全的操作状态。
执行未经授权的代码或命令；读取内存；修改内存
范围: 完整性，机密性
在极少数情况下，当 NULL 等同于 0x0 内存地址且特权代码可以访问它时，就有可能进行内存读写，这可能导致代码执行。

## 预防与缓解措施

阶段
缓解措施
实施
对于任何可能被修改或由可能返回 NULL 的函数提供的指针，在使用前应检查该指针是否为 NULL。在处理多线程或其他异步环境时，请确保在检查前使用适当的锁定 API 进行锁定，并在检查完成后解锁 [
REF-1484
]。
需求
选择一种不易受到此类问题影响的编程语言。
实施
检查所有返回值的函数结果，并在对其采取行动之前验证该值是否为非空。
有效性：中等
注意：
检查函数的返回值通常就足够了，但在并发环境中要提防竞态条件（
CWE-362
）。此解决方案无法处理变量初始化不当的情况（
CWE-665
）。
架构与设计
识别所有从外部源接收信息的变量和数据存储，并应用输入验证以确保它们仅初始化为预期的值。
实施
明确初始化所有变量和其他数据存储，可以在声明时，也可以在首次使用前。

## 官方英文定义（核对锚点）

NULL Pointer Dereference

The product dereferences a pointer that it expects to be valid but is NULL.
