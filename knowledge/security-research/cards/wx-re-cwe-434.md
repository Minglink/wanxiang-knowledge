# CWE-434: 无限制上传危险类型文件

## 缺陷定义

产品允许上传或传输危险文件类型，这些文件会在其环境中被自动处理。

## 可能后果及作用范围

此表指定了与该弱点相关的不同个体后果。“范围”识别被违规的应用安全领域，而“影响”描述如果攻击者成功利用该弱点所产生的负面技术影响。“可能性”提供有关相对于列表中其他后果，特定后果被预期的可能性信息。例如，某种弱点可能极有可能被利用以实现某种影响，但利用它来实现另一种影响的可能性则很低。
影响
详细信息
执行未经授权的代码或命令
范围：完整性、机密性、可用性
如果上传的文件被接收方解析并作为代码执行，则可能导致任意代码执行。对于 Web 服务器扩展（如 .asp 和 .php）尤其如此，因为即使文件系统权限未指定执行，这些文件类型通常也会被视为自动可执行。例如，在 Unix 环境中，程序通常只有在设置了执行位的情况下才能运行，但 PHP 程序可能会被 Web 服务器执行，而无需在操作系统上直接调用它们。

缓解措施
架构与设计
为上传的文件生成一个新的唯一文件名，而不是使用用户提供的文件名，从而完全避免使用外部输入。[
REF-422

架构与设计
策略：
通过转换执行
当可接受对象（如文件名或 URL）的集合有限或已知时，创建从一组固定输入值（如数字 ID）到实际文件名或 URL 的映射，并拒绝所有其他输入。
架构与设计
考虑将上传的文件完全存储在 Web 文档根目录之外。然后，使用其他机制动态提供这些文件。[
REF-423
]
实施
策略：
输入验证
假设所有输入都是恶意的。采用“接受已知良好”的输入验证策略，即使用严格符合规范的可接受输入列表。拒绝任何不严格符合规范的输入，或将其转换为符合规范的内容。
在执行输入验证时，考虑所有潜在相关的属性，包括长度、输入类型、可接受值的全部范围、缺失或额外的输入、语法、跨相关字段的一致性以及对业务规则的符合性。作为业务规则逻辑的一个例子，“boat”在语法上可能是有效的，因为它只包含字母数字字符，但如果输入只预期包含“red”或“blue”等颜色，则它无效。
不要仅仅依赖查找恶意或畸形输入。这很可能会遗漏至少一种不受欢迎的输入，尤其是当代码环境发生变化时。这可能给攻击者留出绕过预期验证的空间。不过，黑名单对于检测潜在攻击或确定哪些输入由于严重畸形而应被直接拒绝是有用的。
例如，将文件名限制为字母数字字符有助于限制引入意外的文件扩展名。
架构与设计
定义一个非常有限的允许扩展名集合，并且仅生成以这些扩展名结尾的文件名。在允许 .html 或 .htm 文件类型之前，请考虑 XSS (
CWE-79
) 的可能性。
实施
策略：
输入验证
确保文件名中只使用一个扩展名。一些 Web 服务器（包括某些版本的 Apache）可能会根据内部扩展名处理文件，从而将 "filename.php.gif" 提供给 PHP 解释器进行处理。[
REF-422
] [
REF-423
]
实施
在支持不区分大小写文件名的 Web 服务器上运行时，请对提供的扩展名执行不区分大小写的评估。
架构与设计
对于在客户端执行的任何安全检查，请确保在服务器端重复这些检查，以避免
CWE-602
。攻击者可以通过在检查执行后修改值，或修改客户端以完全移除客户端检查来绕过这些检查。随后，这些被修改的值将被提交到服务器。
实施
不要仅依赖对文件内容的健全性检查来确保文件是预期的类型和大小。攻击者可能在某些文件段中隐藏代码，这些代码仍将被服务器执行。例如，GIF 图像可能包含自由格式的注释字段。
实施
在确定如何渲染文件时，不要仅依赖 MIME 内容类型或文件名属性。验证 MIME 内容类型并确保其与扩展名匹配只是一个部分解决方案。
架构与设计；运维
策略：
环境强化
使用完成必要任务所需的最低权限来运行代码 [
REF-76
]。如果可能，创建仅用于单个任务的有限权限隔离账户。这样，即使攻击成功，也不会立即让攻击者访问软件的其他部分或其环境。例如，数据库应用程序很少需要以数据库管理员身份运行，尤其是在日常操作中。
架构与设计；运维
策略：
沙盒或囚笼
在“囚笼 (jail)”或类似的沙盒环境中运行代码，该环境在进程和操作系统之间强制执行严格的边界。这可以有效地限制在特定目录中可以访问哪些文件，或者软件可以执行哪些命令。
操作系统级别的示例包括 Unix chroot 囚笼、AppArmor 和 SELinux。通常，受管代码可能会提供一些保护。例如，Java SecurityManager 中的 java.io.FilePermission 允许软件对文件操作指定限制。
这可能不是一个可行的解决方案，并且它仅将影响限制在操作系统层面；应用程序的其余部分仍可能面临被妥协的风险。
小心避免
CWE-243
以及与囚笼相关的其他弱点。
有效性：有限
注：
此缓解措施的有效性取决于所使用的特定沙盒或囚笼的防护能力，可能仅有助于减小攻击范围，例如限制攻击者使用某些系统调用或限制可访问的文件系统部分。
