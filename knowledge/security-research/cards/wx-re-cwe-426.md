# CWE-426: 不受信任的搜索路径

## 缺陷定义

产品使用外部提供的搜索路径来搜索关键资源，该路径可能指向产品无法直接控制的资源。

## 机制与扩展说明

这可能允许攻击者执行自己的程序、访问未经授权的数据文件或以意外方式修改配置。如果产品使用搜索路径来定位程序等关键资源，攻击者可能会修改该搜索路径以指向恶意程序，目标产品随后便会执行该恶意程序。此问题扩展到产品信任的任何类型的关键资源。
不受信任的搜索路径的一些最常见变体包括：
在各种 UNIX 和基于 Linux 的系统中，可能会查询 PATH 环境变量来定位可执行程序，并使用 LD_PRELOAD 来定位单独的库。
在各种基于 Microsoft 的系统中，如果 DLL 在搜索顺序中靠前的其他路径中未找到，则会查询 PATH 环境变量来定位该 DLL。

调用其他程序时，请使用全限定路径名指定这些程序。虽然这是一种有效的方法，但使用全限定路径名的代码可能无法移植到不使用相同路径名的其他系统。通过将全限定路径放置在源代码中集中且易于修改的位置，并让代码引用这些路径，可以提高可移植性。
实施
在调用其他程序之前，删除或限制所有环境变量设置。这包括 PATH 环境变量、LD_LIBRARY_PATH、用于标识代码库位置的其他设置以及任何特定于应用程序的搜索路径。
实施
在使用前检查您的搜索路径，并删除任何可能不安全的元素，例如当前工作目录或临时文件目录。
实施
使用需要显式路径的其他函数。利用任何其他需要显式路径的现成可用函数是避免此问题的安全方法。例如，C 语言中的 system() 不需要完整路径，因为 shell 可以处理它，而 execl() 和 execv() 则需要完整路径。

## 官方英文定义（核对锚点）

Untrusted Search Path

The product searches for critical resources using an externally-supplied search path that can point to resources that are not under the product's direct control.
