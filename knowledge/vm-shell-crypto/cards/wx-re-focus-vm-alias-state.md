# VM上下文建模：别名关系决定优化是否可靠

## 机制

别名分析对两个访问范围给出无重叠、可能重叠或确定重叠等保守信息。虚拟槽可以用不同指针表达同一存储区，字节级与字级访问也可能部分重叠。建模时要比较访问大小和偏移，而不只是指针表达式是否一样。

## 分析例与核对方法

本库构造：向ctx+0写入32位值，随后从ctx+1读取16位。两个地址不相等，但访问范围重叠。若把各槽都声明为独立变量，优化器可能错误保留旧的16位值，破坏解码状态。

## 判断边界

只有在布局和访问证据支持时才拆成独立对象。未知函数可能读写整个上下文，需要保守建模。别名分析返回“可能”不是工具失败，而是在当前信息下避免不可靠优化所需的边界。
