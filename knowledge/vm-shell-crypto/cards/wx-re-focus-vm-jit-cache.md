# JIT与解释器：代码缓存键必须包含影响译码的状态

## 机制

动态翻译把来宾指令块转换为宿主代码并复用。QEMU文档说明查找块会使用PC与其他CPU状态；直接链到后继块可以减少回到主循环的成本。因此分析轨迹时应区分来宾PC、宿主代码地址和翻译缓存身份。

## 分析例与核对方法

本库构造：同一来宾地址在不同模式下有不同指令含义，若缓存键只有地址就会复用错误代码。即使地址不变，原始字节被修改后也应考虑失效条件，不能把旧翻译当成当前字节语义。

## 判断边界

这描述系统动态翻译器的架构原则，与软件保护中的自定义字节码VM不是同一实现。缓存失效、线程同步及中断边界依赖具体引擎，不能用此推断某个商业保护器的内部策略。
