# 保护虚拟机：把指令流建模为状态转移

## 机制

可把一次虚拟指令记为 S_next = H(opcode, S)，状态包含虚拟程序计数器、虚拟栈/寄存器和可见内存。解释器负责取指、选择处理器并更新状态；CPU执行的是解释器的本机指令，业务语义却编码在字节码中。识别时同时记输入状态、读写位置、输出状态和下一字节码位置。

## 分析例与核对方法

本库构造：PUSH 3、PUSH 5、ADD把空虚拟栈变成[8]。本机轨迹可能包含大量地址计算，业务效果仍只是加法。若只记录最后的物理寄存器，很容易把分发临时值误认成结果。

## 判断边界

栈机、寄存器机和混合结构都可能出现，栈顶也可能缓存在寄存器内。状态字段应通过读写关系确认；“某个寄存器永远是VPC”只能是当前样本假设，不能作为所有保护器的固定规则。
